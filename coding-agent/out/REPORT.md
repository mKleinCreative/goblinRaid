**Chose:** stealth_detection

It is the only candidate that wins on every criterion at once: explicitly Never cut, scheduled for week 1 with that week already past, and completely absent rather than partially scaffolded. It is also the widest unblocker left — the alarm system has phase and source enums but literally no code that can emit a signal into them; takedown needs an unaware state; the Scout's crouch stance has no detection consumer to modify; noise investigation reuses the same perception spine; and First Spark Unseen needs a confirm counter to track. Crucially it is one-pass buildable in pure C++: a per-observer perception component with a ~1.5s confirm timer that resets on LOS loss, a watchman vision cone with a doze droop, crouch and cover range modifiers, and a SightingConfirmed event that fires exactly one soft signal moving the town to Suspicious. No art, no animation, no level content, no dependency on unbuilt systems.

**Runner-up rejected because:** alarm_phase_system loses because it is the consumer, not the producer. Build the four-phase subsystem now and you get a state machine with zero inputs: none of its six soft signals — confirmed sighting, corpse, startled flock, patrol horn, overdue patrol, civilian census — have an emitter in the codebase, and four of those emitters belong to features (town_defenders, civilian_routines) that are week 5-6 and near the top of the cut order. It also cannot be delivered coherently in one pass, since it demands investigate BT behaviour and RAZED-phase spawner silencing alongside the phase logic. It is not Never cut, where detection is. Detection first gives the alarm hub a real, testable first signal to be built around next.

## Generated

Adds the crouch-and-confirm detection spine from GDD §2.4 as a new Stealth/ folder in GoblinSiege, with no edits to existing files. GSStealthTypes.h defines the stance enum (Standing/Crouched/Hidden), a data-driven FGSDetectionTuning (base range, crouch multiplier, full-cover multiplier, 1.5s confirm hold, forget window, cone half-angle) with the stance x cover x doze range fold-in, an FGSDozeTuning for the watchman droop, and the per-target FGSSightingRecord. UGSSightPerceptionComponent lives on guards, ticks at 20Hz on the server, and per target: rejects on range, tests the (possibly drooping) cone, traces five silhouette sample points to get an exposure fraction that scales the effective range via the cover multiplier, then accumulates ConfirmTimer while visible and hard-resets it to zero the instant line of sight breaks — an early-broken look is no signal at all. When the hold reaches 1.5s the record latches bConfirmed, broadcasts OnSightingConfirmed and calls into UGSStealthSubsystem exactly once. The doze timer accrues only while the guard sees nobody and the town is below Raid; it pitches the view direction down, narrows the cone, shortens range, and is reset by Rouse() or any sighting, with a debug cone that recolours by confirm state. UGSStealthSubsystem (world subsystem) owns the stealth-target registry (explicit registrations plus every player pawn automatically), resolves stance off ACharacter::bIsCrouched with an override map, de-duplicates confirms per observer/target inside an 8s window, emits the single soft signal by calling AGSGameState::ReportConfirmedSighting() (Quiet -> Suspicious) on the server only, counts confirms, and snapshots First Spark Unseen on the first NotifyFirstObjectiveIgnited() call, broadcasting the verdict.

### Integration steps

1. Add a UGSSightPerceptionComponent to the guard/watchman blueprints (or in AGSEnemyCharacter's constructor via CreateDefaultSubobject if you prefer C++ ownership); leave bCanDoze on for static watchmen and clear it on roving patrols.
2. Call UGSStealthSubsystem::Get(this)->NotifyFirstObjectiveIgnited() from the first ignition path (AGSBurnObjectiveBase / AGSBuildingObjective ignition) so the First Spark Unseen verdict is snapshotted at the right moment.
3. Read UGSStealthSubsystem::IsFirstSparkUnseen() from the end-of-raid scoring path (UGSScoreSubsystem) to pay out the First Spark Unseen bonus.
4. Register non-player sneaking actors (AI goblins, AGSHordeGoblin) with RegisterStealthTarget on BeginPlay; player pawns need no registration.
5. Set SetStanceOverride(Actor, EGSStealthStance::Hidden) when a goblin is downed/dead or inside a scripted hide so guards stop accumulating on a corpse.
6. Bind UGSSightPerceptionComponent::OnSightingConfirmed (or the subsystem's OnStealthConfirmSignal) from the guard AI controller to drive the investigate/aggro branch, and call Rouse() from the future noise system.
7. Enable bDrawDebugVisionCone in PIE to eyeball the droop and the confirm hold; swap in a cone mesh later aimed at GetVisionDirection().

### Risks the agent flagged

- Detection ticks server-only, so on a dedicated-server client the vision cone art driven by GetVisionDirection() will not droop (DozeSeconds stays 0 clientside). A replicated doze alpha or a client-side predicted timer is a follow-up.
- No Watchman actor class was added — the component is drop-in on any existing guard pawn, but the post-placement 'watchman stands here and dozes' actor with its patrol/idle behaviour is a follow-up.
- Cover exposure uses five line traces against ECC_Visibility only; foliage or cover set to a different collision channel will read as fully exposed. A dedicated cover trace channel is a follow-up tuning pass.
- The subsystem's confirm de-duplication is time-windowed per observer/target pair (8s default); a guard who loses and re-finds the same goblin inside that window emits no second signal, which is intentional for now but is not the same as the §2.6 corroboration rule proper.
- Noise, corpse sightings and coin tosses only have the Rouse() hook — none of them are wired, so nothing currently resets a dozing guard except an actual sighting.
- No automation tests; the 1.5s hold and the LOS-loss reset were verified by construction and debug draw, not by a functional test.
