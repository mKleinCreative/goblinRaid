### 2. Human locomotion yoyo — CAUSE FOUND AND FIXED, needs eyes on it

Michael: *"it's like the pivot doesn't move with the animation, and they snap back after he takes 2
steps"*, then, after opening the asset itself: *"the error looks like it's playing the clip and
yoyoing."*

**Cause, measured with `AnimationLibrary.extract_root_track_transform`:** every human locomotion clip
has TRAVEL BAKED INTO THE ROOT BONE while `enable_root_motion` is **False**. Nothing consumes the
motion, so the mesh slides and resets every loop.

| clip | length | root travel |
|---|---|---|
| `A_HU_Std_WalkF` | 1.33s | **223.3uu** |
| `A_HU_Std_WalkB` | 1.37s | 207.9uu |
| `A_HU_Std_WalkL` / `WalkR` | ~1.25s | 191.3 / 221.6uu |
| `A_HU_Std_RunF` | 0.73s | **298.0uu** |
| `A_HU_Std_RunB` | 0.80s | 249.8uu |
| `A_HU_Std_RunL` / `RunR` | ~0.7s | 342.7 / 397.5uu |
| `A_HU_Std_Idle` | 1.83s | 0.0 — correct |

**FIX APPLIED:** `force_root_lock = True` on all 8 travelling clips (Idle untouched). Saved and
confirmed modified in `git`. Root-lock rather than enabling root motion, because these feed a blend
space driving AI whose position comes from the navmesh — root motion would fight path-following.

**NOT OBSERVED.** Preview `A_HU_Std_WalkF` and watch it cycle in place; then PIE. If residual stutter
remains once the root is pinned, the two suspects below are still live and neither is ruled out:

   (`AI/GSAISteeringComponent.cpp:406`) while path-following drives velocity. Toggle with
   `GS.Combat.Separation 0` **on a MOVING guard** — I only ever tested it on a stationary one, which
   proved nothing.

## GOTCHAS THAT COST REAL TIME TODAY

0. **DO NOT TRUST A "RULED OUT" IN THIS DOCUMENT UNLESS IT NAMES THE MEASUREMENT.** Two conclusions
   in this session were asserted from a property read-back and were wrong (the human animation clips
   above; the "Locomotion State inexistent" warning). Both cost hours and one was written down as
   settled. If a claim does not say what was sampled and what the number was, re-check it.
1. **`save_loaded_asset` / `save_asset` SILENTLY RETURN FALSE and the change is lost.** It happened to
   `DA_Race_Human` (reverted on editor restart — nearly reported a fix that never existed) and to
   `DA_Char_Militia`. **Use `EditorLoadingAndSavingUtils.save_packages(get_dirty_content_packages())`
   and then VERIFY on disk** (file mtime + `git status`). Never trust the return value.
2. **During PIE there is no editor world.** `get_all_level_actors()` returns 0 and `BlueprintService`
   returns no graphs. I twice read that emptiness as "the actors were deleted". **Call
   `IsPIERunning` before believing any empty result.** Blueprint edits during PIE silently no-op.
3. **Three source comments are STALE and actively misleading** (corrected in `AGENT_STATE.md:42-50`
   today, but the source comments themselves still lie):
   - `GSAIControllerBase.h:13-16` — "ACF's OnPossess early-returns … our RunBehaviorTree calls remain
     load-bearing". **False since Phase 2a.**
   - `GSCharacterMovementComponent.cpp:18-20` — "with the bands gone … sets MaxWalkSpeed to ZERO …
     the restore is not optional". **False** — ACF's miss branch
     (`ACFCharacterMovementComponent.cpp:677-692`) is **log-only**. `"Locomotion State inexistent"` is
     a marker, NOT a cause. I built an entire wrong plan on that warning.
   - `AGENT_STATE.md` also claimed `BT_Militia` has no EdGraph — it does; Michael edited it in the BT
     editor.
4. **A downward line trace is NOT a ground test.** It must exclude fog cards, the water plane, the
   `GS_ForestWall_*` blockers **and the InstancedFoliageActor itself** — a tree's own trunk masks the
   test. 566 of 572 birches were "verified" that way and never actually tested.
5. **Python cannot build an `FGameplayTag`** — use `unreal.GSRaidLibrary.make_tag_by_name(name, True)`.
   An empty tag stringifies as `"None"`, so `name or "<none>"` reads a blank tag as set.
6. **`EditDefaultsOnly` struct fields refuse `set_editor_property`** — `export_text()` / `import_text()`
   on the struct bypasses it. That is how `DA_Race_Human`'s archetype tree was changed.
7. **Frames can be pulled from an .mp4 with no ffmpeg** — PowerShell `-STA` + WPF `MediaPlayer` +
   `DrawingVisual.DrawVideo` + `RenderTargetBitmap`. Michael sends screen recordings; this works.
8. **BT editor at zoom < −3 stops rendering pins**, so wires cannot be dragged while menus still work.
   Also: tasks have only an input pin — children of a Sequence fan out, they do not chain.
