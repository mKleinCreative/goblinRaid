## OPEN, IN-PROGRESS: FIELD FIRE VISUAL ("looks like rows of fires, not one spreading mass")

Michael's complaint, and the reason for the Niagara Fluids detour. Chronology, so the next session
doesn't re-walk it:

1. Scaled pooled fire volumes to actually overlap (`bAutoScaleFXToRadius` + tuned
   `FireSystemAuthoredRadius`, scoped to `ConfigurePooled` only - torch-thrown single fires
   untouched). Helped, not enough - most of the burning band still had NO flame on it at all.
2. Raised `MaxFireVolumes` 10 -> 16 (its own `ClampMax` ceiling) so more of a wide burning front
   actually gets a flame instance.
3. Added per-instance `SetRandomSeedOffset` so neighbouring volumes don't play identical patterns
   (was reading as "stamped copies").
4. **Verdict after 1-3: still rows.** Swapped `FireSystem` to the Niagara Fluids prototype
   (`NG_GS_SurfaceFireLiquid`) as a live A/B test. **Still rows**, even as a fluid sim - because the
   fundamental issue was never the rendering technology. It's that each pooled volume is still its
   own separate, independently-bounded instance sitting in a grid position. N separate instances in a
   line read as N separate things, sprite or fluid.

**The actual fix, scoped but NOT built:** decouple the VISUAL from the DAMAGE. Keep the existing
pooled `AGSFireVolume`s for damage exactly as they are (per-cell, invisible - turn off their own
`FireFX`), and add ONE wide fire-visual actor sized/repositioned every cosmetic tick to span the
*bounding box* of all currently-burning cells (not just `GetBurningCentroid()`, which only gives the
average position - need a sibling that tracks min/max extent). Open risks written down in the
conversation, worth re-reading before starting: disconnected fronts (two separate ignition points
not yet merged - would need per-cluster visuals, not one box spanning empty ground between them),
resize smoothness (must lerp toward target extent, not snap), Niagara Fluids domain-resize cost at
runtime (untested), and burnout fade (the one wide visual needs its own fade-out, independent of each
pooled volume's own expiry).

**Before touching this: revert the `FireSystem` test swap in `GSFireVolume.cpp`'s constructor** (see
BUILD STATE above) unless the plan is to build the new architecture around the fluids system
specifically.

## GOTCHAS FROM THIS SESSION (also in `CLAUDE.md` - read that copy, this is a pointer)

- **Leaked background PowerShell/Bash processes from timed-out MCP tool calls can eat 20-25GB of RAM
  each**, and read exactly like an in-engine memory leak or a hung editor. Hit this TWICE this
  session, once crashing the Epic Games Launcher via OOM. Check `Get-Process powershell | Sort
  WorkingSet64 -Descending` before chasing an engine-side leak after a string of timed-out calls.
- **`unreal.EditorAssetLibrary.save_loaded_asset`/`save_asset` return `False` even when the save
  genuinely succeeds** (and, separately, sometimes really do skip the save with no error). Trust the
  engine log (`Saving Package` / `Moving output files`) and the file's own `LastWriteTime`, never the
  Python return value.
- **`dithered_lod_transition` on a material meant for foliage, inherited by a plain placed mesh, can
  make it fully invisible at any distance** with every other property reading normal. See #365 above
  and the full CLAUDE.md gotcha for the fix pattern and the `to_dict()` trap on
  `MaterialInstanceBasePropertyOverrides`.
- **`FindObjectiveAtLocation`-style "first match wins" dispatch across differently-shaped hit-tests is
  a real bug class** - a coarse/large-area check (the field) can silently steal hits meant for a
  precise one (a structure) with zero symptom other than "the precise thing never seems to light."
  Worth grepping for other places this project does a similar first-match iteration over dissimilar
  candidates.
- **Niagara Fluids' 2D solver is production-viable as of UE5.6/5.7** (confirmed via web search this
  session, not stale knowledge) - real-time-safe with predictable GPU budget, unlike the 3D solver
  which stays cinematic-only. Plugin is NOT scriptable to enable via Python in this project; manual
  Edit > Plugins > search "Niagara Fluids" > enable > restart, same as the Cascade-to-Niagara
  converter before it.
